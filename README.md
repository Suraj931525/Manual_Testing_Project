## 📌 Project Overview

This repository contains my **Manual Software Testing project** completed during my Software Testing internship at **Cravita Technologies**.

The project focuses on testing the **Sales Order module of the InFlow Inventory Management System**. The objective was to validate the functionality, usability, data validation, and overall behavior of the module by designing test scenarios, preparing test cases, executing tests, identifying defects, and performing retesting and regression testing.

The project demonstrates practical knowledge of the **Software Testing Life Cycle (STLC)** and real-world QA documentation.

---

## 🎯 Project Objective

The main objectives of this project were:

* Understand and analyze application requirements.
* Identify test scenarios for the Sales Order module.
* Design detailed manual test cases.
* Execute positive and negative test cases.
* Verify actual results against expected results.
* Identify and document defects.
* Perform defect retesting after fixes.
* Perform regression testing.
* Maintain testing documentation.
* Validate that the Sales Order functionality works according to requirements.

## 📋 Test Scenarios

Test scenarios were prepared to cover the major functionalities of the Sales Order module.

The scenarios include:

### Functional Scenarios

* Verify Sales Order page functionality.
* Verify customer selection.
* Verify product/item selection.
* Verify quantity field.
* Verify mandatory fields.
* Verify order details.
* Verify Sales Order creation.
* Verify successful submission.
* Verify validation messages.
* Verify incorrect input handling.

### Positive Scenarios

* Enter valid customer information.
* Select a valid product.
* Enter valid quantity.
* Provide all mandatory information.
* Create a Sales Order using valid data.
* Verify successful order submission.

### Negative Scenarios

* Leave mandatory fields blank.
* Enter invalid data.
* Enter invalid quantity.
* Submit the form without required information.
* Verify validation messages.
* Verify the system behavior for incorrect inputs.

## 🔄 Retesting & Regression Testing

After defects were fixed, the affected functionality was **retested** to verify that the reported issue had been resolved.

Regression testing was also performed on related functionality to ensure that the new changes did not negatively affect previously working features.

### Retesting

```text
Bug Identified
      ↓
Bug Reported
      ↓
Developer Fix
      ↓
Retest Failed Functionality
      ↓
Verify Expected Result
```

### Regression Testing

```text
New Fix
  ↓
Identify Related Features
  ↓
Execute Existing Test Cases
  ↓
Compare Results
  ↓
Confirm No New Defects
```

## 🧠 Test Design Techniques

The project demonstrates practical use of manual testing techniques such as:

### Equivalence Partitioning

Dividing input data into valid and invalid groups to reduce the number of test cases while maintaining effective coverage.

### Boundary Value Analysis

Testing values at the boundaries of acceptable input ranges.

### Negative Testing

Providing invalid or unexpected input to verify that the application handles errors correctly.

### Error Guessing

Using tester experience to identify possible failure conditions that may not be explicitly mentioned in requirements.
